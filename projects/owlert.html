Hackathon Project

Owlert

A desk robot with local AI inference that catches negative habits, doomscrolling, bad posture, low water intake, in the moment. Built with a team at HackMIT; my part was the electronics: wiring the hardware and bringing up the Arduino UNO Q.

View on GitHub →

Overview

Owlert is a desk robot that watches for the small habits people fall into while working: doomscrolling, slouching, forgetting to drink water. A camera feeds a locally run AI model that classifies what it sees, so the robot can react in the moment instead of waiting for an end-of-day summary.

It runs on an Arduino UNO Q and is fully self-contained, powered off a single 9V battery. Servos let it turn and tilt, and a small display stands in for its eyes so it can look expressive rather than just log data silently. A companion web dashboard tracks each habit’s count against a daily limit, so what Owlert notices on-device shows up somewhere to review later.

Tech Stack

  • Arduino UNO Q
  • Local AI Inference
  • Custom CV Model
  • Servos
  • OpenAI Astra
  • ElevenLabs API
  • Devin

Key Features

  • A camera feeds a model trained specifically on our habit classes (doomscrolling, bad posture, low water intake); tailored to that narrow task, it runs roughly 2× faster than YOLO Nano, fast enough for local inference on the board.
  • The whole robot, camera, compute, and actuation, is self-contained and runs off a single 9 V battery, showing the setup works as cheap, affordable inference rather than needing a wall outlet or a beefy compute box.
  • Servos turn and tilt the head, and a small display doubles as expressive eyes, so Owlert can react visibly to what it sees instead of only logging it.
  • A companion web dashboard shows active habits and daily check-ins, so the counts Owlert notices on-device are there to review later, not just acted on in the moment.
  • Roles were split by whoever was free and had the most relevant experience: a mix of system design, low-level implementation, construction, and electronics. My part was the electronics: wiring the hardware and bringing up the Arduino UNO Q.
  • The hardest hardware problem was powering a USB camera through the UNO Q without the recommended powered USB hub, which wasn’t available on-site. A stripped USB-A cable wired to a bench supply didn’t work, so the camera path had to be reworked live during the event.
  • Explored an ElevenLabs voice integration, built almost end-to-end with Devin, as a stretch goal; the current version has no speakers, but the API is already wired up for a future revision.
